# v0.2 Next-Phase Roadmap — embedsync

**Status:** v0.2.0 shipped (hash embedder, paragraph chunking, JSONL destination; real pgvector still open)  
**Target Version:** 0.2.0 – 0.6.0  
**Owner:** Yash Shah  
**Last Updated:** 2026-08-19  

---

## 1. Executive Summary

Evolve embedsync from a **sync planner with in-memory stub** into a **production RAG index maintenance tool**: write to pgvector and Qdrant, call pluggable embedding functions, track stable chunk IDs across edits, ingest Notion and sitemap sources, and diff at chunk granularity to minimize re-embedding cost.

## 3. Milestone Breakdown

### Milestone M1 — pgvector Destination (v0.2.0)

**Goal:** Write embeddings and metadata to PostgreSQL with pgvector extension — the most common self-hosted vector store.

#### Deliverables

- [ ] `embedsync/destinations/pgvector.py` — `PgVectorDestination` class
- [x] JSONL destination as a local stand-in (`jsonl:/path`)
- [ ] Connection config via env (`EMBEDSYNC_PG_DSN`) or CLI `--destination pgvector://...`
- [ ] Auto-create table schema: `doc_id`, `chunk_id`, `content`, `embedding vector(N)`, `metadata JSONB`
- [x] Upsert on ADD/UPDATE; DELETE by `doc_id` on DELETE action (memory + JSONL)
- [ ] Batch insert with configurable `--batch-size 100`
- [ ] Integration test with Postgres + pgvector in `compose.yaml`
- [ ] `examples/pgvector/` — docker-compose stack + sample sync

#### Schema Design

| Column | Type | Description |
|--------|------|-------------|
| `chunk_id` | TEXT PRIMARY KEY | Stable chunk identifier |
| `doc_id` | TEXT NOT NULL | Source document ID |
| `content` | TEXT | Chunk text |
| `embedding` | vector(1536) | Configurable dimension |
| `metadata` | JSONB | Source path, heading, etc. |
| `updated_at` | TIMESTAMPTZ | Last sync timestamp |

#### Acceptance Criteria

| # | Criterion |
|---|-----------|
| AC1 | `embedsync run ./docs --destination pgvector` writes rows to Postgres |
| AC2 | Re-run with no changes performs 0 embedding calls and 0 DB writes |
| AC3 | Document delete removes all chunks for that `doc_id` |
| AC4 | Works with `openai` embedding dimension (1536) and `nomic-embed` (768) |

#### Dependencies

- M3 pluggable embedding (pgvector writes require real vectors)
- `psycopg[binary]` optional extra
- pgvector extension in test Postgres container

#### Risks

| Risk | Mitigation |
|------|------------|
| Vector dimension mismatch | Validate embedder output dim vs table schema at startup |
| Large batch OOM | Configurable batch size; streaming insert |

**Estimate:** 2 weeks

### Milestone M2 — Qdrant Destination (v0.3.0)

**Goal:** Support Qdrant Cloud and self-hosted Qdrant as an alternative vector backend.

#### Deliverables

- [ ] `embedsync/destinations/qdrant.py` — `QdrantDestination` class
- [ ] Connection via `EMBEDSYNC_QDRANT_URL` + optional API key
- [ ] Auto-create collection with configured vector size and distance metric
- [ ] Point ID = `chunk_id`; payload = `{doc_id, content, metadata}`
- [ ] Upsert on ADD/UPDATE; delete by `doc_id` filter on DELETE
- [ ] Integration test with Qdrant container in compose
- [ ] Destination protocol abstraction — shared interface for pgvector and Qdrant

#### Destination Protocol

```python
class Destination(Protocol):
    def apply(self, action: SyncAction, chunks: list[Chunk], dry_run: bool) -> None: ...
    def delete_doc(self, doc_id: str, dry_run: bool) -> None: ...
    def close(self) -> None: ...
```

#### Acceptance Criteria

| # | Criterion |
|---|-----------|
| AC1 | Sync to local Qdrant container succeeds with 2 example docs |
| AC2 | UPDATE replaces points for changed document only |
| AC3 | DELETE removes all points matching `doc_id` payload filter |
| AC4 | Same sync plan produces equivalent results on pgvector and Qdrant |

#### Dependencies

- M1 pgvector (shared destination protocol extracted from M1)
- `qdrant-client` optional extra

#### Risks

| Risk | Mitigation |
|------|------------|
| Qdrant point ID format constraints | Use UUID derived from chunk_id hash |
| Collection recreation on dim change | Detect mismatch; fail with clear migration instructions |

**Estimate:** 1–2 weeks

**Goal:** Turn chunk text into vectors via configurable embedders — required before any real destination works.

- [ ] Token counting + truncation before embed (configurable `max_tokens`)

#### Embedder Registry

| Provider | Config | Default Model | Dim |
|----------|--------|---------------|-----|
| `openai` | `OPENAI_API_KEY` | `text-embedding-3-small` | 1536 |

| # | Criterion |

| AC2 | Ollama embedder works locally without cloud API key |

### Milestone M4 — Stable Chunk IDs (v0.3.0)

**Goal:** When a document is edited, identify unchanged chunks by content hash and re-embed only modified chunks — the core cost optimization.

#### Deliverables

- [x] Chunk-level re-embed on document edits (content-hash per chunk)
- [x] Extend SQLite state: `chunks` table with `(chunk_id, doc_id, content_hash)`
- [ ] `plan_sync()` returns chunk-level ADD/UPDATE/DELETE within changed documents
- [ ] `--full-reindex` flag to force re-embed all chunks for a doc
- [ ] Diff report: `embedsync plan ./docs --verbose` shows per-chunk actions
- [ ] Migration path from v0.1 document-level state (one-time full reindex)

#### State Schema Extension

```sql
CREATE TABLE chunks (
    chunk_id TEXT PRIMARY KEY,
    doc_id TEXT NOT NULL,
    content_hash TEXT NOT NULL,
    chunk_index INTEGER NOT NULL,
    FOREIGN KEY (doc_id) REFERENCES documents(doc_id)
);
```

#### Chunk Diff Logic

| Scenario | Action |
|----------|--------|
| New chunk at end of doc | ADD chunk |
| Middle chunk edited | UPDATE chunk (new embedding) |
| Chunk removed | DELETE chunk |
| Doc deleted | DELETE all chunks for doc_id |
| Unchanged chunk (same content_hash) | SKIP (no embed, no DB write) |

#### Acceptance Criteria

| # | Criterion |
|---|-----------|
| AC1 | Edit one paragraph in a 10-chunk doc → exactly 1 chunk UPDATE, 9 SKIP |
| AC2 | Stable chunk IDs persist across sync runs for unchanged content |
| AC3 | `--full-reindex` re-embeds all chunks regardless of hash |
| AC4 | State migration from v0.1 triggers one-time full reindex with warning |

#### Dependencies

- M3 real chunker (chunk boundaries must be deterministic)
- M1 pgvector (verify skip logic reduces DB writes)

#### Risks

| Risk | Mitigation |
|------|------------|
| Chunk boundary shift on edit cascades re-embeds | Investigate semantic chunking (future); document limitation |
| State DB growth | Periodic `embedsync state vacuum` command |

**Estimate:** 2 weeks

### Milestone M5 — Notion + Sitemap Sources + Chunk-Level Diff (v0.4.0)

**Goal:** Ingest remote document sources and finalize chunk-granularity sync as the default behavior.

#### Deliverables

- [ ] `embedsync/sources/notion.py` — `NotionSource` via Notion API
- [ ] `embedsync/sources/sitemap.py` — `SitemapSource` crawls URLs from sitemap.xml
- [ ] Source config YAML: `sources.yaml` with type, credentials, include/exclude patterns
- [ ] Notion: page ID as doc_id, block-to-markdown conversion
- [ ] Sitemap: URL as doc_id, HTML-to-text extraction (readability/trafilatura)
- [ ] Rate limiting and retry for HTTP sources
- [ ] Chunk-level diff enabled by default (M4); document-level diff deprecated
- [ ] `embedsync run --source notion|sitemap|local` or auto-detect from config
- [ ] PyPI publish pipeline

#### Source Config YAML

```yaml
source:
  type: notion
  database_id: abc123
  api_key: ${NOTION_API_KEY}
  include:
    - "Published"
destination:
  type: pgvector
  dsn: ${EMBEDSYNC_PG_DSN}
embedder:
  provider: openai
  model: text-embedding-3-small
chunker:
  strategy: markdown
  chunk_size: 512
  chunk_overlap: 64
```

#### Acceptance Criteria

| # | Criterion |
|---|-----------|
| AC1 | Notion source lists pages from a test database; sync plan shows ADD for new pages |
| AC2 | Sitemap source crawls `examples/sitemap.xml` and extracts text content |
| AC3 | Chunk-level diff is default; editing one Notion block triggers single-chunk UPDATE |
| AC4 | `pip install embedsync[notion,qdrant,openai]` installs all optional deps |
| AC5 | PyPI package installable and `embedsync health` succeeds |

#### Dependencies

- M4 stable chunk IDs (chunk-level diff is the culmination)
- M2 Qdrant (validate multi-destination with remote sources)
- M3 embedder (remote sources require real embeddings)

#### Risks

| Risk | Mitigation |
|------|------------|
| Notion API rate limits | Exponential backoff; `--since` incremental fetch |
| Sitemap crawl scope explosion | `--max-pages 1000`; robots.txt respect |
| HTML extraction quality | Pluggable extractor; fallback to raw text |

**Estimate:** 3 weeks

## 6. Out of Scope (Deferred)

- Pinecone, Weaviate, Milvus destinations
- Confluence, Google Docs, GitHub wiki sources
- Hosted SaaS sync dashboard
- Real-time webhook-driven sync (batch CLI only)
- Hybrid search (BM25 + vector) index management
- Multi-tenant or ACL-aware sync

## 7. Recommended Execution Order

1. **M3** Pluggable embedding + real chunker (unblocks all destinations)
2. **M1** pgvector destination (first real vector backend)
3. **PyPI publish** (distribution unlock)
4. **M4** Stable chunk IDs (core cost optimization)
5. **M2** Qdrant destination (second backend, validates abstraction)
6. **M5** Notion + sitemap sources (remote ingestion)

**Total estimated timeline:** 10–12 weeks for v0.2–v0.4 with one developer.
